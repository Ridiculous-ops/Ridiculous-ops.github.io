各类常用软件安装
#

CUDA
#

运行 spack install cuda@version%gcc@xxx 即可。

需要注意 CUDA 的编译器兼容矩阵(https://gist.github.com/ax3l/9489132)，如 CUDA 10.2.89 最高兼容到 GCC 8.2.0，版本太高会导致 nvcc 无法编译程序。

此外，由于 CUDA 中只有 binary，一个版本的 CUDA 只需要安装一次。如果在其他地方需要用到 CUDA 但是编译器版本不一致（通常是比 CUDA 标记的版本要低），在人工确定可以使用的情况下，直接使用 ^/hash 的形式强制指定 CUDA 版本即可。

一般来说，一个大版本（major）只需要一个 CUDA 版本，因为 cudart 等动态库都是兼容的。

UCX
#

ucx 是MPI的重要依赖，操作系统本身安装的ucx并不一定带有cuda支持，所以需要手动安装ucx，并且在安装OpenMPI时指定该ucx的版本。

spack spec ucx # 查看包依赖关系 同时也可以查看默认情况下的flag情况
spack info ucx # 查看版本和参数

安装
# 

# ucx 1.14.1之后才支持cuda12编译安装
spack install ucx@1.14.1 +cuda+cma+dc+dm+gdrcopy+ib_hw_tm+mlx5_dv+rc+ud+rdmacm+verbs+thread_multiple

检查
#

  • 检查 ucx 是否包括 cuda(–with-cuda)/knem(–with-knem)/gdrcopy(–with-gdrcopy)/thread_multiple(–enable-mt) 支持：ucx_info -v
  • 检查 ucx 是否识别IB卡, ucx_info -d | grep mlx
  • 检查 ucx 的编译选项是否符合预期ucx_info -b

OpenMPI
#

为了使用 IB，必须使用 UCX 作为底层通信实现。通常需要打开多线程支持。如果需要直接传递 GPU buffer（一般应用会说明是否需要，HPL 可能需要），则需要编译 CUDA Aware MPI （注意这样会使得编译出的 MPI 程序依赖 libcudart.so，所以可以保留两个是否 aware 的版本）。

注意：OpenMPI 不依赖于 Mellanox OFED 的任何用户态组件（如 rdma-core），Spack 会自行安装他们。只要确认内核态驱动已经安装完成，即存在 /dev/infiniband/* 设备，即可开始安装。

相应的编译选项为：spack install openmpi@version +cuda fabrics=ucx "^ucx/<hash>" +cuda。如果想要指定 CUDA 版本，可以在后面加上 ^cuda/xxxxxxx。

注意thread_multiple只适用于2之前的版本的openmpi,3以后的版本是默认打开的，而且无法更改，如果强制选择会安装老版本的mpi，所以这个flag可以不设。

singularity类似docker，在CS23中出现过，故也选择安装,但由于spack中singularity的版本过于老旧，建议手动安装。

编译非 cuda aware 的 MPI：spack install openmpi@version +thread_multiple fabrics=ucx "^ucx"

此外，gdrcopy 可以提高传递 GPU buffer 的性能，需要在所有机器上编译和安装 gdrcopy 内核模块以及开发库（推荐编译成 DKMS 的 deb），然后使用以下选项：

spack install openmpi@version +cuda +thread_multiple fabrics=ucx "^ucx" +cuda +gdrcopy

类似的，还有 knem，类似 gdrcopy 的方法写 +knem 即可。

注意，ucx 也要选用 +cuda 的版本。

检查
#

检查 openmpi 是否包括 cuda(–with-cuda)/ucx(–with-ucx) 支持：ompi_info --parsable | grep cuda/ucx

检查安装正确性：osu-micro-benchmarks

spack install osu-micro-benchmarks ^openmpi/hash

$(which mpirun) -host i1:1,i2:1 $(which osu_bw)

跑出来的带宽应该与IB的理论带宽接近。

如果系统里自带了 Slurm，可以先添加 slurm 到 ~/.spack/packages.yml 里：

packages:
  slurm:
    externals:
    - spec: slurm@20-11-8
      prefix: /usr

然后 install openmpi 的时候添加 +pmi +legacylaunchers schedulers=slurm

Intel 系列
#

首先需要将申请的（或者白嫖的） License 文件放置在 /opt/intel/licenses 下。

安装下列软件的方法：

  • ICC：spack install intel@version
  • Intel MPI：spack install intel-mpi@version%intel@version（注意与编译器版本对应）
  • Intel MKL：spack install intel-mkl@version%intel@version（注意同上）
  • VTune 等：spack install intel-parallel-studio@cluster.xxx +vtune +advisor（注意需要是 cluster 版本）

也可以用 oneAPI：https://spack.readthedocs.io/en/latest/build_systems/inteloneapipackage.html

  • ICC：spack install intel-oneapi-compilers@version

CUDA
#

用 spack 安装，GCC 版本兼容性：

  • CUDA 11.0: <= 9
  • CUDA 11.1: <= 10
    # Linux x86_64 compiler conflicts from here:
    # https://gist.github.com/ax3l/9489132
    arch_platform = ' target=x86_64: platform=linux'
    conflicts('%gcc@5:', when='+cuda ^cuda@:7.5' + arch_platform)
    conflicts('%gcc@6:', when='+cuda ^cuda@:8' + arch_platform)
    conflicts('%gcc@7:', when='+cuda ^cuda@:9.1' + arch_platform)
    conflicts('%gcc@8:', when='+cuda ^cuda@:10.0.130' + arch_platform)
    conflicts('%gcc@9:', when='+cuda ^cuda@:10.2.89' + arch_platform)
    conflicts('%gcc@:4', when='+cuda ^cuda@11.0.2:' + arch_platform)
    conflicts('%gcc@10:', when='+cuda ^cuda@:11.0.2' + arch_platform)
    conflicts('%gcc@11:', when='+cuda ^cuda@:11.1.0' + arch_platform)
